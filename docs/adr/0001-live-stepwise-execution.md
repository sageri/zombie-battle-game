# 逐行动实时执行（步进引擎）而非整场预计算回放

可视化战斗呈现时，更简单的做法是把整场战斗一次性算完、再按序回放；我们决定让界面按行动顺序逐步驱动引擎——每一步都是引擎当下真实结算的一个行动，演出的就是这个结算。这保住了呈现的真实性（看到的每步不是录像），也为未来中途交互（如手动介入战斗）留了接口；代价是引擎要同时维护步进与整场两套 API，并以「同一种子下两路径终局状态与日志完全一致」的一致性测试锁死（见 `verify/engine.test.mjs`）。

## Considered Options

- **整场预计算回放（被否）**：实现最简单，但呈现的是录像而非战斗，且堵死中途交互的路。
- **逐行动实时执行（采纳）**：本 ADR 的决定，理由如上。
