# 编成制与固定同额配点预算替代自由属性配置

战前决策从「人数 + 四属性自由输入」换血为**编成制**：兵种＝固定四属性模板＋点数成本（人类 4 型 / 丧尸 5 型，阵营专属表），每阵营在**固定同额 32 点**配点预算内购置「兵种×数量」，人数由编成内生（每边 1–36），允许不满用。角色名＝兵种名＋型内序号（守卫1、尸潮3），`state.members` 新增 `typeId`（JSON 纯数据，不进任何判定）；默认编成＝特色三人组（人类 守卫+枪手+侦察兵 / 丧尸 腐行者+撕裂者+疾行者，恰 32/32）。这是冻结面「配置校验语义」的一次性授权换血（#18 规格 V1–V8 逐条对应）：旧六类属性校验消息废止，`GameEngine.NAME_PREFIX` 移除，`UNIT_TYPES` / `POINT_BUDGET` 新增导出。战斗函数、日志文案与随机数消费机制一行不动——均衡型（民兵/丧尸）与旧默认属性同值，同种子一致（ADR 0001）结构性保持，由一致性套件继续执法。

## Considered Options

- **自由属性输入 + 兵种预设下拉（被否）**：保留旧配置面只是加快捷键，配置环节仍然没有取舍——任何「最优先行」数值一经发现就锁死玩法。
- **微调层（兵种基础值 + ±加点）（被否）**：多一层配置状态与校验规则，策略深度增量配不上复杂度。
- **纯配点（直接买 hp/攻/敏/伤害点数）（被否）**：自由度回到旧问题，且角色失去辨识度（名字、Emoji 都无依托）。
- **新旧两制共存开关（被否）**：两套配置 UI、两套校验并行，测试面翻倍；切换无玩法意义。
- **预算随人数可调 / 预算做成可选值（被否）**：「买多少」本身成了第一层决策，分散编成取舍的注意力；固定同额 32 点让所有编成同台可比。
- **两阵营共用一张兵种清单（被否）**：对称好测，但抹掉阵营玩法个性；阵营专属表让「人类坦克」与「丧尸肉盾」各有性格。
- **编成制 + 固定同额 32 点（采纳）**：本 ADR 的决定。攻/敏上限 6 保证「必中/必闪」边界仍由骰子说话；预算 32 恰容特色三人组，逼出「肉盾换火力、物量换质量」的取舍；改动收敛在 `engine.js` 授权五区段与 `ui.js` 配置页，冻结面其余部分零触碰。
